# The function surface

Every §4.3 function and operator, against every shape a value can have. 44
files, 1,419 probes, both engines.

## Why this set is not a selection

The other sets are chosen cases: somebody thought of a construct and wrote it
down. That is the exact limitation the coverage ledger exists to work around one
layer up — such a test can only fail on an input somebody thought of — and the
function library had the same hole for its whole existence.

Nothing in the corpus had ever put **text where a number belongs**, because
until dataset columns existed nothing could: every value in a form came from a
typed question. A CSV holds nothing but text (§3.2), so `int($row.population)`
made it an everyday case overnight, and the first two dataset vectors that used
one failed on Kotlin. The sweep that followed ran every function and operator
against every value shape on both engines:

> **762 of 1,395 probes disagreed.** Most were one engine raising while the
> other returned null. The worst were both returning a value and the values
> differing. Three functions — `regex`, `substr`, `distance` — were declared in
> §4.3, implemented in the Python reference, and **not implemented at all** in
> the Kotlin engine, so a form using one threw on a device and worked on the
> server. The UCL biomass form's phone-number constraint uses `regex`.

None of it had a vector. Break 46.

So this set is the cross product, and its whole value is that nobody picked the
cases.

## The rule it encodes

Form IR §4.7:

- an argument that is not of the type §4.3 declares is `null`, and a function
  with such an argument yields `null`
- **evaluation raises for exactly one reason: integer overflow** (§4.5)
- `eq` / `ne` are total across types — two values of different types are simply
  not equal, which is `false`, not null
- `concat` renders rather than refuses

## Where the expectations come from

`fn.spec.json` is typed **by hand from §4.7's own table** and is the anchor. The
generator refuses to write it if the reference disagrees with the spec, so the
two cannot drift silently.

The other 43 files are generated by evaluating the Python reference, which
docs/project-conventions.md makes the definition where behaviour is ambiguous. They were reviewed
by shape class against the rule rather than row by row — 1,419 rows reviewed
individually is a review nobody does properly, and the class table is what the
rule is actually about.

Regenerating after a deliberate semantic change is legitimate, and is a spec
change. Regenerating to make a failure go away is what rule 3 forbids.

```bash
python conformance/generate_function_matrix.py
cd backend && pytest tests/test_function_conformance.py -v
./gradlew :shared:form-engine:jvmTest
```
